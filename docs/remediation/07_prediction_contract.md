# Standardized Prediction Contract Specification

**Document Version:** 1.0.0  
**Phase:** P07 Native Dual-Core Predict-Then-Optimize Pipeline  
**Target:** Aeolus Gate Optimization Framework  

---

## 1. Overview & Purpose

In a Predict-then-Optimize decision support system, the prediction contract serves as the formal boundary between machine learning forecasting engines and downstream operations research solvers. 

This document defines the schema, semantic rules, role-based access controls, and validation requirements for all flight delay predictions consumed by the Aeolus Gate Assignment and Reassignment solvers.

---

## 3. Target Semantics & Signed Delay Invariants

1. **Signed Delays Preserved:** Delay estimates represent signed continuous minutes relative to scheduled clock times:
   - $\Delta > 0$: Flight operates behind schedule (delayed).
   - $\Delta = 0$: Flight operates exactly on schedule.
   - $\Delta < 0$: Flight operates ahead of schedule (early arrival or early pushback).
2. **No Zero-Flooring:** Early movements MUST NOT be clamped to zero at inference time. Clamping early arrivals distorts occupancy windows and prevents realistic simulation of gate pre-emption.
3. **Pushback Target vs Wheels-Off:** The Core Departure target `DEP_DELAY` specifically models gate-out / pushback delay. Models predicting runway wheels-off time (`TAXI_OUT + DEP_DELAY`) are categorized as auxiliary models and are forbidden from downstream gate planning unless a validated taxi-out model is applied.

---

## 4. Provenance Modes

Every prediction artifact MUST declare its provenance mode explicitly:

1. **`NATIVE_INFERENCE`:**
   - Inferences are dynamically generated in-memory by loading an authorized checkpoint via `verify_and_load_checkpoint` and running `predict()` or `predict_distribution()` on raw tabular inputs.
   - Checkpoint file hash must match pre-registered SHA-256 digest.
2. **`PRECOMPUTED_PREDICTION`:**
   - Predictions read from static benchmark tables or historical out-of-fold (OOF) parquet stores.
   - Permitted only for baseline comparisons; cannot be represented as live ML inference.
3. **`SYNTHETIC_SIMULATION`:**
   - Artificial delay realizations generated by Monte Carlo sampling, synthetic stress injection, or sensitivity analysis.
4. **`SCHEDULE_BASELINE`:**
   - Nominal schedule with zero predicted delays ($\Delta = 0.0\text{ min}$).

## 5. Model Role-Based Access Control (RBAC)

Downstream gate optimization strictly enforces model access control through [`src/optimization/adapter.py`](file:///D:/Study/Code/Python/Aelous/src/optimization/adapter.py):

| Model Category | Task Enum | Allowed Downstream? | Required Certification | Failure Action |
| :--- | :--- | :---: | :--- | :--- |
| **Core Arrival** | `CORE_ARRIVAL` | **YES** | `downstream_eligible=True` | `UncertifiedModelError` |
| **Core Departure** | `CORE_DEPARTURE` | **YES** | `selection_role="GATE_OUT_PREDICTION"`, `downstream_eligible=True` | `UncertifiedModelError` |
| **Auxiliary Departure** | `AUXILIARY_DEPARTURE` | **NO** | Research-only; strictly forbidden | `RoleAccessViolationError` |
| **Research Candidates** | Various | **NO** | Deferred / Experimental | `UncertifiedModelError` |

## 6. Distributional Parameters Validation

When probabilistic models (e.g. Student-T, Heteroscedastic Gaussian) are evaluated:
1. **Finiteness:** Parameters $\mu, \sigma, \nu$ must be finite real numbers.
2. **Positivity:** Scale parameter $\sigma$ must satisfy $\sigma > 0$.
3. **Heavy-Tail Regularity:** Degrees of freedom $\nu$ for Student-T distributions must satisfy $\nu > 2$ to guarantee finite variance.
4. **Quantile Monotonicity:** Quantiles must be strictly non-decreasing:
   $$Q_{0.10} \le Q_{0.50} \le Q_{0.90}$$
5. **No Synthetic Fabrication:** Point regressors MUST NOT invent fake probability estimates ($P \ge 15$) or fabricate standard deviations.
